# Задача для агента: система этапов и пилотная тема «Функции»

Репозиторий: `ascezis/vkat_py` («вкат.py», офлайн-тренажёр по Python, вычисления на Pyodide). К промпту приложен файл урока «Функции в Python — самостоятельная работа» (источник контента пилота).

## 0. Зачем это нужно

Автор проекта преподаёт Python. Ученики прошли весь текущий тренажёр, но он сводится к знакомству с конструкциями: задания короткие, условие называет нужную конструкцию, в подсказке лежит готовое решение. Реальные задачи в классе ученики решают с трудом.

Цель: добавить второй этап курса — углублённый. Он повторяет темы первого этапа на рабочем уровне: теория, вопросы, предсказание вывода, поиск ошибок, задачи без подсказки с названием конструкции. Первый этап («Начало») остаётся как есть.

Главное продуктовое требование: тренажёр должен **разгрузить преподавателя**. Он объясняет тему 10–15 минут, дальше ученики работают сами около часа. Отсюда три правила, которые важнее красоты решений:

1. **Нельзя ложно отклонять верные решения.** Каждый такой случай возвращает преподавателя к ученику. Проверка идёт по поведению, не по форме. Формат вывода всегда однозначно описан в условии.
2. **Обратная связь понятна ребёнку.** Сообщения об ошибках и о провале теста объясняют, что не так, а не показывают сырой traceback.
3. **Помощь ступенчатая.** Ученик получает помощь без преподавателя: объяснение ошибки, затем подсказки по возрастанию.

Сегодняшняя сессия: **только фундамент и одна пилотная тема.** Остальные темы этапа 2, бэкенд, панель преподавателя, песочница и т.п. сейчас не делаем (см. раздел 7).

## 1. Жёсткие ограничения

- Только HTML, CSS и vanilla JS. Без фреймворков, сборщиков и npm-зависимостей в том, что получает ученик.
- Скрипты подключаются классическими тегами `<script>` и работают через IIFE и `window.*`, как сейчас. **ES-модули не использовать**: они не работают при открытии через `file://`. Не использовать `fetch` для локальных файлов по той же причине.
- Полностью офлайн: никаких внешних запросов.
- Pyodide работает в основном потоке, как сейчас. **Web Worker не вводить.** Защиту от бесконечных циклов (`_inject_loop_guard`) сохранить.
- Дизайн строго по `docs/design-system.md`: никаких новых цветов, теней и скруглений. Если токена не хватает, переиспользуй существующий.
- Содержимое и `id` заданий этапа «Начало» не менять. Сохранённый прогресс учеников в `localStorage` должен продолжать работать.
- Код-комментарии и тексты интерфейса на русском, как сейчас.

## 3. Обзор решения

- Курс состоит из **этапов**. Этап содержит **темы**, тема содержит **элементы** (items): теория, задания, вопросы.
- Этап `start` («Начало») = шесть текущих тем без изменений.
- Этап `core` (временное название «Основной курс») = углублённые версии тех же тем. Сегодня в нём одна тема: «Функции».
- Метка «Level 0/1» нигде в интерфейсе не показывается: только названия этапов.

## 4. Архитектура

### 4.1 Описание этапов

Новый файл `content/stages.js`, подключается до тем:

```js
window.COURSE_STAGES = [
  {
    id: 'start',
    title: 'Начало',
    description: '…',                       // для карточки на стартовом экране
    topics: [/* реальные id шести текущих тем в текущем порядке */],
    finish: { title: 'Базовый разрыв закрыт!', text: '…' }   // текст перенести из index.html
  },
  {
    id: 'core',
    title: 'Основной курс',                 // временное название, должно легко меняться
    description: '…',
    topics: ['l1_functions'],
    note: 'Пока доступна одна тема, остальные появятся позже',
    finish: { title: '…', text: '…' }
  }
];
```

Реальные `id` тем этапа `start` возьми из файлов `content/01…06`. Темы, не перечисленные ни в одном этапе, при загрузке дают `console.warn`.

### 4.2 Плоский список тем и совместимость состояния

При запуске строится плоский упорядоченный массив тем: сначала темы этапа 1 в порядке `topics`, затем этапа 2. Каждой теме проставляется `stageId`. Индексы существующих тем при этом не меняются, поэтому сохранённая позиция (`vkat_current_position`: индекс темы и индекс задания) остаётся валидной. Если сохранённая позиция указывает на несуществующий элемент, откат на начало.

Тема может задавать список элементов в поле `tasks` (как сейчас) или `items` (новое). При загрузке нормализуй: `topic.items = topic.items || topic.tasks`.

### 4.3 Модель элемента

Общие поля: `id` (глобально уникальный и стабильный), `type`, `title`. Элемент без `type` — это `code` (все задания этапа «Начало»).

| `type` | Поля | Поведение |
|---|---|---|
| `theory` | `blocks[]` | Страница для чтения. Блоки: `{type:'p', html}`, `{type:'code', code, output?}`, `{type:'list', items:[html]}`, `{type:'table', head:[…], rows:[[…]]}`, `{type:'note', html}`. Кнопка «Дальше» отмечает элемент пройденным. В прогресс не входит |
| `code` | как сейчас: `explanation[]`, `example`, `assignment`, `starterCode`, `expectedOutput`, `astRequirements`, `testCode`, `improveTip`, `successMessage`; новое: `hints[]`, `tests[]`, `tier`, `optional`, `kind` | Редактор и проверка (раздел 4.4) |
| `predict` | `explanation[]?`, `code`, `expectedOutput`, `explain` | Слева условие, справа код только для чтения и поле ответа «Что выведет программа?». После отправки код запускается по-настоящему, показываются фактический вывод, совпал ли ответ, и текст `explain`. **Пройденным считается после первой отправки, неверный ответ не блокирует** |
| `quiz` | `question`, `code?`, `options[]`, `correct` (индекс), `explain` | Выбор варианта. Неверный ответ показывает сообщение и разрешает повторить. Пройденным считается при верном ответе. После ответа показывается `explain` |

Поля `code`-задания:
- `tier`: `'warmup' | 'main' | 'star'` (по умолчанию `'main'`). В интерфейсе маленькая метка: «разминка», «основное», «★».
- `optional`: `true` для `star` по умолчанию. Необязательные задания можно пропустить кнопкой «Пропустить».
- `kind: 'fix'`: метка «найди ошибку». В `starterCode` лежит код с ошибкой.
- `hints[]`: ступенчатые подсказки, элемент — строка (текст, допускается HTML) или `{code: '…'}` (показывается с подсветкой). Старое поле `hint` (строка) трактуется как `hints: [{code: hint}]`. Кнопка «подсказка 1 из N» раскрывает следующую подсказку.
- `tests[]`: описание в разделе 4.4.

**Подсчёт прогресса:** проверяемые элементы = `code`, `predict`, `quiz`. Обязательные = проверяемые без `optional`. Прогресс этапа = пройденные обязательные / все обязательные этапа. Элементы типа `theory` и необязательные задания в прогресс-бар не входят, но получают отметку ✓ в дереве. В `completedTasks` могут лежать id любых элементов, при подсчёте фильтруй.

### 4.4 Проверка (`app/checker.js`)

Контракт `CodeChecker.checkSolution(userCode, task)` сохраняется. Порядок проверки:

1. AST: синтаксис, существующие `require_*`, **новые флаги** (ниже).
2. Выполнение кода ученика в защищённом виде (как сейчас).
3. `expectedOutput`, если задан (как сейчас).
4. **`tests[]`** (новое).
5. `testCode` (как сейчас, для уровня 0).
6. Линтер, как сейчас.

**Новые флаги `astRequirements`:**
- `forbid_calls: ['max', 'min']`: запрещённые вызовы по имени. Сообщение: «В этом задании нельзя использовать max().»
- `forbid_methods: ['sort']`: запрещённые методы (`x.sort()`).
- `require_calls: ['draw_line']`: в коде должен быть вызов функции с таким именем. Сообщение: «В решении нужно вызвать функцию draw_line.»

Существующие флаги и сообщения не менять.

**`tests[]`.** Каждый тест — объект:

```js
{ call: 'double(7)', returns: 14 }
{ call: 'draw_line(5)', stdout: '*****' }
{ call: 'rectangle(4, 2, "@")', stdout: '@@@@\n@@@@' }
{ call: 'is_even(0)', returns: true, hidden: true }
```

Семантика:
- `call` — строка Python, вычисляется через `eval` в пространстве имён кода ученика (`_user_ns`), которое сохраняется после выполнения кода. Вывод (`stdout`) во время вызова перехватывается отдельно для каждого теста с гарантированным восстановлением `sys.stdout` (`try/finally`).
- `returns` сравнивается так: ожидается `bool` → результат строго `bool`; ожидается `str` → строка; ожидается число → `int` или `float`, но не `bool`, сравнение по `==` (то есть `2` и `2.0` равны). `None`: `is None`.
- `stdout` сравнивается с нормализацией (убрать пробелы в концах строк и пустые строки по краям, как в `normalizeOutput`).
- Если указаны оба, проверяются оба. Если указан только `stdout`, возвращаемое значение игнорируется.
- Если у задания есть `tests`, а `expectedOutput` не задан, общий вывод программы ученика **не сравнивается**: ученик вправе добавить собственные вызовы и `print`.
- `hidden: true`: при провале вызов не раскрывается. Сообщение: «Не пройден дополнительный тест. Проверь граничные случаи: ноль, пустая строка, отрицательные числа.» (текст можно переопределить полем `hiddenTestHint` задания).
- Показывается **только первый** проваленный тест: «Вызов `is_even(0)` вернул `False`, ожидалось `True`», для `stdout` аналогично с выводом.
- Если при вызове возникло исключение: «При вызове `rectangle(5, 3)` произошла ошибка: …» плюс дружелюбное пояснение (раздел 4.5).
- Если вызываемое имя не найдено (`NameError` на самом имени функции): «Функция `name` не найдена. Проверь, что она объявлена через def и имя совпадает с условием.»
- Результат содержит поле `failedTest` (call, ожидаемое, фактическое) для страницы самопроверки.

**Новая публичная функция** `CodeChecker.runCode(code)`: выполняет код с защитой от циклов и перехватом вывода, возвращает `{stdout, error}`. Используется в `predict` и на странице самопроверки.

Тесты вызывают функции, объявленные в уже защищённом (`_inject_loop_guard`) коде. Отдельная защита вызовов не нужна.

### 4.5 Подсказки и дружелюбные ошибки

Подсказки: раздел 4.3 (`hints[]`).

**Пояснение ошибок.** Новый модуль (например, `app/errors.js`) с таблицей «шаблон сообщения → пояснение для ученика» (Приложение B). Сопоставление идёт по тексту traceback и по сообщению `SyntaxError`. Пояснение показывается отдельным блоком «что это значит» рядом с консолью ошибки: в той же визуальной системе, без новых цветов. Работает для ошибок выполнения, синтаксических ошибок и ошибок вызова в `tests`. Этап «Начало» получает это бесплатно, регрессий быть не должно.

### 4.6 Интерфейс

- **Стартовый экран:** карточки этапов вместо трёх цифр «6 / 26 / 1–2». На карточке: название, описание, число тем и заданий (считать из контента), прогресс, кнопка «Начать» или «Продолжить», у этапа `core` примечание `note`. Заголовок и подзаголовок стартового экрана сохраняются, без перерисовки. Кнопка «Продолжить» ведёт на первый непройденный обязательный элемент выбранного этапа.
- **Дерево оглавления:** сгруппировано по этапам (заголовок этапа, затем темы и элементы). Элементы типов `theory`, `predict`, `quiz` и необязательные отмечены иконкой или меткой в стиле дерева. Переход по клику на любой элемент.
- **Экран урока:** режим правой панели зависит от типа. `code`: как сейчас. `predict`: код только для чтения и поле ответа. `quiz`: варианты ответа. `theory`: использовать всю ширину (правую панель скрыть или растянуть левую). Хлебные крошки: «название этапа · тема · шаг N из M» (в нижней строке и в `topbar`, регистр как сейчас).
- **Точки шагов внизу:** тема может содержать до ~25 элементов, обеспечь компактность. Элементы `theory` отличаются от проверяемых.
- **Полоса прогресса сверху:** прогресс текущего этапа по обязательным элементам.
- **Кнопки:** `code` обязательный: «Следующее» только после прохождения, как сейчас. Необязательный: всегда доступна «Пропустить». `theory`: «Дальше». `predict` и `quiz`: «Проверить», затем «Следующее».
- **Финальный экран по этапам:** показывается после последнего элемента последней темы этапа. Берёт текст из `finish` этапа. Кнопки: «Дальше: <название следующего этапа>» (если он есть) и «Повторить этап». Повтор сбрасывает прогресс и черновики **только этого этапа**, с подтверждением. Текущий `restartCourse()` заменить на сброс по этапу.
- Все числа считать из контента: никаких зашитых 6 и 26 в `index.html`.

### 4.7 Хранилище

Ключи `vkat_completed_tasks`, `vkat_code_drafts`, `vkat_current_position` сохраняются. Черновики по `id` элемента (в том числе ответы `predict`). Добавить `vkat_schema = 2` для будущих миграций, миграцию сегодня не писать.

## 6. Пилотная тема «Функции»

Файл `content/l1-04-functions.js`, регистрирует тему `{ id: 'l1_functions', title: 'Функции', minutes: 60, items: [...] }`. Состав и порядок элементов, тесты, эталоны и неправильные решения даны в **Приложении A и проверены**: все эталоны проходят свои проверки, все неправильные решения отклоняются. Структуру менять не нужно, тексты нужно написать.

Как писать тексты:
- Теорию (`theory`) и разборы бери из приложенного файла урока. Адаптируй для тренажёра: убери отсылки к «учителю», «соседу», «файлу `functions.py`», «набирай руками» и всё, что рассчитано на бумажный формат. Раздел «Для преподавателя» ученику не показывать, но им можно пользоваться как источником разборов и подсказок.
- Обращение «ты», тон как в текущих темах: спокойный, без восклицательных знаков и эмодзи.
- Для каждого `code`-задания напиши 3 подсказки: (1) идея без кода, (2) каркас с пропусками `___`, (3) готовое решение. Опционально `improveTip` и `successMessage` (одна строка).
- В условии указывай точный формат вывода и точные имена функций. Формулировки в Приложении A можно причесать, но формат и имена сохраняются.
- Копию урока положи в `docs/lessons/functions.md` как исходник.

### 6.1 Самопроверка (`dev/selftest.html`)

Отдельная страница (в `index.html` не подключается), использует те же скрипты и тот же `CodeChecker`. Эталоны и неправильные решения лежат **отдельно от контента**, чтобы не попадать в пакет ученика: файл `dev/selftest/l1-functions.js` регистрирует `window.COURSE_SELFTEST['<id>'] = { reference: '…', wrong: [{ name: '…', code: '…' }] }`.

Страница делает:
1. **Валидация структуры курса:** все `id` глобально уникальны; обязательные поля по типам; `correct` в диапазоне; `hints` непустые у `code`-заданий этапа 2; все темы этапов существуют; в `tests` есть `call`.
2. **Прогон эталонов:** `checkSolution(reference, task)` обязана вернуть `passed: true`.
3. **Прогон неправильных:** каждое `wrong` обязано вернуть `passed: false`.
4. **Прогон `predict`:** `runCode(code).stdout` совпадает с `expectedOutput` после нормализации.

Вывод: таблица (задание, проверка, статус, причина при провале), общий итог вверху. Это основной инструмент автора для проверки качества контента.

## Приложение B. Пояснения к ошибкам

Сопоставляй по подстроке или регулярному выражению в тексте ошибки. Формулировки можно слегка подправить, но смысл и тон сохранить. Список можно расширять по мере появления случаев.

| Шаблон | Пояснение для ученика |
|---|---|
| `IndentationError` (expected an indented block, unexpected indent, unindent does not match) | Строки внутри функции, цикла или условия сдвигаются на 4 пробела вправо. Остальной код пишется без отступа. |
| `SyntaxError: expected ':'` | В конце строки с `def`, `if`, `elif`, `else`, `for`, `while` нужно двоеточие. |
| `SyntaxError`: `was never closed`, `unmatched`, `unterminated string literal` | Не хватает или лишняя скобка или кавычка. Проверь, что каждая открывающая скобка и кавычка закрыта. |
| `NameError: name 'X' is not defined` | Python не знает имя X. Проверь написание (регистр важен), создана ли переменная или функция до использования, и не создана ли она внутри функции: снаружи она не видна. |
| `TypeError` + `missing … required positional argument` | Функции передано меньше аргументов, чем параметров в `def`. Сравни вызов со строкой `def`. |
| `TypeError` + `positional argument(s) but … given` | Функции передано больше аргументов, чем параметров в `def`. |
| `TypeError` + `unsupported operand type(s)` + `NoneType` | Один из операндов равен `None`. Скорее всего, функция печатает результат через `print`, а нужно вернуть его через `return`. |
| `TypeError` + `can only concatenate str` или `unsupported operand type(s) for +: 'int' and 'str'` | Строку и число нельзя сложить через `+`. Преврати число в строку через `str(x)` или перечисли значения через запятую в `print`. |
| `ZeroDivisionError` | Деление на ноль. Добавь проверку делителя перед делением. |
| `IndexError: list index out of range` | Такого индекса нет в списке. Индексы начинаются с 0, последний элемент: `len(a) - 1` или `a[-1]`. |
| `KeyError` | Такого ключа нет в словаре. Проверь написание ключа или используй `get`. |
| `ValueError: invalid literal for int()` | Строку нельзя превратить в число: в ней есть не только цифры. |
| `AttributeError: … has no attribute …` | У значения такого типа нет этого метода. Проверь имя метода и тип значения. |
