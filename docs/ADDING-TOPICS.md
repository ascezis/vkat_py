> Этот документ описывает весь цикл работы с контентом:
> от идеи до появления темы в приложении. Никаких знаний о
> внутреннем коде приложения не требуется — только JSON-подобный
> синтаксис JavaScript.

## 1. Архитектура контента

```
content/
  stages.js          ← определяет этапы (разделы) курса
  start/             ← темы вводного раздела (01-06)
    01-variables.js
    02-conditions.js
    ...
  core/              ← темы основного курса (l1-*)
    l1-03-lists.js
    l1-04-functions.js
    ...
```

**Как это работает:**

1. `stages.js` объявляет `window.COURSE_STAGES` — порядок разделов и список тем в каждом.
2. Каждый файл темы вызывает `window.COURSE_TOPICS.push({...})` — добавляет тему в глобальный реестр.
3. `index.html` подключает все файлы через `<script src="...">`.
4. При запуске `app.js` объединяет `COURSE_STAGES` и `COURSE_TOPICS` в плоскую структуру.

> **Важно:** Файлы темы не зависят друг от друга и от кода приложения.
> Один файл = одна запись в `COURSE_TOPICS`.

---

## 2. Шаг 1 — Создать файл темы

Создайте файл в соответствующей папке контента:

```
content/start/07-my-topic.js    ← для вводного раздела
content/core/l1-06-my-topic.js  ← для основного курса
```

**Минимальный шаблон:**

```javascript
/**
 * Тема: <Название>
 * Раздел: start | core
 */

window.COURSE_TOPICS = window.COURSE_TOPICS || [];

window.COURSE_TOPICS.push({
  id: "my_topic",          // уникальный snake_case идентификатор
  title: "Название темы", // отображается в интерфейсе
  items: [
    // Массив учебных элементов. Порядок важен!
  ]
});
```

> **Заметка:** Ключ `tasks` — устаревший псевдоним `items`. Поддерживается,
> но в новых темах всегда используй `items`.

---

## 3. Шаг 2 — Зарегистрировать тему в этапе

В `content/stages.js` добавьте `id` темы в массив `topics` нужного этапа:

```javascript
window.COURSE_STAGES = [
  {
    id: "start",
    title: "Старт",
    topics: [
      "variables",
      "conditions",
      "loops",
      "functions",
      "lists",
      "strings",
      "my_topic"   // ← добавьте сюда
    ]
  },
  // ...
];
```

> **Важно:** `id` в `stages.js` должен **точно** совпадать с полем `id` файла темы.
> Приложение выведет предупреждение в консоль, если тема заявлена, но не найдена.

---

## 4. Шаг 3 — Подключить файл в index.html

В `index.html` добавьте `<script>` в блок своего раздела:

```html
<!-- Файлы тем контента: раздел 1 "Старт" (start) -->
<script src="content/start/01-variables.js"></script>
...
<script src="content/start/07-my-topic.js"></script>  <!-- ← добавьте -->
```

## 5. Справочник типов элементов

Каждый элемент в `items[]` — объект с полем `type`.
Если `type` не указан, элемент считается `code`.

---

### 5.1 `code` — задание на написание кода

Ученик пишет Python в редакторе. Код проверяется через Pyodide.

```javascript
{
  id: "my_topic_c1",       // [обязательно] уникальный ID в рамках всего курса
  type: "code",             // [необязательно] дефолтный тип
  title: "Название шага",  // [обязательно]

  // Объяснение — массив абзацев (рендерится как <p>)
  explanation: [
    "Первый абзац объяснения.",
    "Второй абзац с <b>HTML</b> внутри."
  ],

  // Пример с кодом и выводом (опционально)
  example: {
    code: "x = 5\nprint(x * 2)",
    output: "10"
  },

  // Текст задания
  assignment: "Напиши программу, которая выводит число 42.",

  // Начальный код в редакторе (опционально)
  starterCode: "# Напиши код здесь\n",

  // Ожидаемый вывод stdout (сравнивается побайтово после trim)
  expectedOutput: "42",

  // AST-требования (опционально, см. раздел 6)
  astRequirements: {
    requireFor: true,
    requireDef: true,
    forbid: ["while"]
  },

  // Ступенчатые подсказки (опционально)
  hints: [
    { text: "Используй функцию print()." },
    { text: "Передай число напрямую:", code: "print(42)" }
  ],

  // Сообщение при успехе (опционально)
  successMessage: "Отлично! Первый шаг пройден.",

  // Совет «Как сделать лучше» (показывается после успешной проверки)
  improveTip: "Хорошим тоном считается добавлять пустую строку в конце файла.",

  // Уровень сложности (влияет на бейдж)
  // "warmup" = разминка, "main" = обычное (дефолт), "star" = звёздочка (необязательное)
  tier: "warmup",

  // Тип задания
  // "fix" = «найди ошибку» (в starterCode намеренно ошибка)
  kind: "fix"
}
```

**Слои проверки кода:**

| Слой | Что проверяет | Блокирует переход? |
|------|--------------|-------------------|
| 1. Выполнение | stdout совпадает с `expectedOutput` | ✅ да |
| 2. AST-анализ | `astRequirements` — наличие/отсутствие конструкций | ✅ да |
| 3. PEP8-линтер | отступы, snake_case, длина строк | ❌ нет (только совет) |

### 5.2 `theory` — страница теории

Ученик читает теорию. Кнопки «Проверить» нет — только «Дальше».
Шаг засчитывается при переходе автоматически.

```javascript
{
  id: "my_topic_t1",
  type: "theory",
  title: "Как работают списки",
  blocks: [
    // Абзац с HTML
    { type: "p", html: "Список — это <b>упорядоченная</b> коллекция элементов." },

    // Блок кода с опциональным выводом
    {
      type: "code",
      code: "fruits = ['яблоко', 'банан']\nprint(fruits[0])",
      output: "яблоко"
    },

    // Маркированный список
    {
      type: "list",
      items: [
        "Элементы нумеруются с нуля.",
        "Список можно изменять после создания."
      ]
    },

    // Таблица
    {
      type: "table",
      head: ["Метод", "Что делает"],
      rows: [
        ["append(x)", "добавляет x в конец"],
        ["pop()",     "удаляет последний элемент"]
      ]
    },

    // Плашка-предупреждение
    { type: "note", html: "Индекс <code>-1</code> означает <em>последний</em> элемент." }
  ]
}
```

### 5.3 `predict` — предсказание вывода

Ученику показывают готовый код Python. Его задача — написать точный вывод.
**Засчитывается после первой отправки** (даже при неверном ответе).

```javascript
{
  id: "my_topic_p1",
  type: "predict",
  title: "Что выведет эта программа?",

  // Необязательное объяснение
  explanation: [
    "Внимательно проследи порядок вызовов print()."
  ],

  // Код, который видит ученик
  code: "x = 3\ny = x * 2\nprint(x)\nprint(y)",

  // Ожидаемый вывод (РЕКОМЕНДУЕТСЯ — избегает запуска Pyodide)
  expectedOutput: "3\n6",

  // Объяснение ответа (показывается после проверки)
  explain: "Сначала выводится x=3, затем y=x*2=6."
}
```

> **Совет:** Всегда указывай `expectedOutput` — это ускоряет проверку
> и исключает зависимость от Pyodide.

---

### 5.4 `quiz` — вопрос с вариантами

Тест с единственным верным ответом. При ошибке можно попробовать снова.

```javascript
{
  id: "my_topic_q1",
  type: "quiz",
  title: "Проверочный вопрос",

  // Текст вопроса
  question: "Что произойдёт при обращении к индексу за пределами списка?",

  // Код для демонстрации (опционально)
  code: "items = [1, 2, 3]\nprint(items[5])",

  // Варианты ответа
  options: [
    "Вернётся None",
    "Программа завершится с ошибкой IndexError",  // ← верный (индекс 1)
    "Вернётся последний элемент",
    "Вернётся 0"
  ],

  // Индекс верного ответа (0-based!)
  correct: 1,

  // Объяснение (показывается только при верном ответе)
  explain: "Python не допускает выход за границы списка и бросает IndexError."
}
```

## 6. Продвинутые возможности

### Звёздочные задания (`tier: "star"`)

Необязательное задание. Отображается со значком ★ в боттомбаре,
не блокирует переход к следующей теме.

```javascript
{ id: "...", tier: "star", ... }
```

### Разминка (`tier: "warmup"`)

Простейшее задание в начале темы. Бейдж «разминка».

```javascript
{ id: "...", tier: "warmup", ... }
```

### Задача «Найди ошибку» (`kind: "fix"`)

`starterCode` намеренно содержит ошибку. Бейдж «найди ошибку».

```javascript
{
  id: "...",
  kind: "fix",
  starterCode: "print 'Привет'  # Python 2 синтаксис — исправь!\n",
  expectedOutput: "Привет",
  ...
}
```

### Ступенчатые подсказки

Кнопка «Подсказка» открывает их одну за другой.

```javascript
hints: [
  { text: "Подумай, какую функцию использовать." },
  { text: "Нужна функция len().", code: "print(len(my_list))" },
  { code: "print(len(fruits))  # полное решение" }
]
```

### AST-требования

Заставляют ученика использовать определённые конструкции:

```javascript
astRequirements: {
  requireFor:   true,    // обязателен хотя бы один for
  requireWhile: true,    // обязателен хотя бы один while
  requireIf:    true,    // обязателен хотя бы один if
  requireDef:   true,    // обязательно def (определение функции)
  forbid: ["while"]      // запрещает использование while
}
```

> **Осторожно:** используй `forbid` только когда принципиально важно,
> чтобы ученик применил именно конкретную конструкцию.

## 7. Чеклист перед коммитом

```
□ Все id уникальны в рамках всего курса
□ Тема добавлена в stages.js (stages.topics[])
□ Файл подключён в index.html
□ expectedOutput указан для всех code и predict элементов
□ starterCode не содержит готового решения
□ Тема начинается с theory-блока (рекомендуется)
□ Открыт dev/selftest.html — все тесты зелёные
□ Запущен python dev/run_tests.py — всё прошло
```

**Быстрая проверка уникальности ID (PowerShell):**

```powershell
Select-String -Path "content\*\*.js" -Pattern '"id":\s*"' |
  ForEach-Object {
    if ($_.Line -match '"id":\s*"([^"]+)"') { $matches[1] }
  } |
  Group-Object | Where-Object Count -gt 1
```

## 8. Частые ошибки

| Симптом | Причина | Решение |
|---------|---------|---------|
| Тема не появляется | `id` не совпадает со `stages.js` | Смотри `console.warn` в DevTools |
| Тема в неправильном порядке | Неверный порядок в `stages.topics[]` | Переставь `id` в `stages.js` |
| Проверка всегда проваливается | `expectedOutput` не совпадает с реальным stdout | Скопируй точный вывод из Python |
| AST-задание не засчитывается | Ученик обошёл требование | Проверь поля `requireFor` / `forbid` |
| Файл не грузится | Опечатка в `src=` пути | Проверь регистр (Linux чувствителен) |

## 9. Пример: полная тема с нуля

Добавим тему «Кортежи» в раздел `core`.

**Шаг 1 — Создаём** `content/core/l1-07-tuples.js`:

```javascript
/**
 * Тема: Кортежи
 * Раздел: core
 */

window.COURSE_TOPICS = window.COURSE_TOPICS || [];

window.COURSE_TOPICS.push({
  id: "l1_tuples",
  title: "Кортежи",
  items: [
    {
      id: "l1_tuples_t1",
      type: "theory",
      title: "Что такое кортеж",
      blocks: [
        {
          type: "p",
          html: "Кортеж (<code>tuple</code>) — это <b>неизменяемый</b> список. После создания его нельзя изменить."
        },
        {
          type: "code",
          code: "point = (10, 20)\nprint(point[0])",
          output: "10"
        },
        {
          type: "note",
          html: "Попытка изменить элемент кортежа вызовет <code>TypeError</code>."
        }
      ]
    },
    {
      id: "l1_tuples_c1",
      tier: "warmup",
      title: "Создание кортежа",
      explanation: ["Создай кортеж из трёх элементов и выведи его длину через len()."],
      assignment: "Создай кортеж rgb = (255, 128, 0) и выведи len(rgb) на экран.",
      starterCode: "# Создай кортеж rgb\n",
      expectedOutput: "3",
      hints: [
        { text: "Кортеж создаётся через круглые скобки: rgb = (255, 128, 0)" },
        { code: "print(len(rgb))" }
      ]
    },
    {
      id: "l1_tuples_q1",
      type: "quiz",
      title: "Кортеж vs список",
      question: "Что произойдёт при попытке выполнить: t = (1, 2, 3); t[0] = 99?",
      options: [
        "Первый элемент изменится на 99",
        "Кортеж автоматически станет списком",
        "Программа завершится с ошибкой TypeError",
        "Создастся новый кортеж"
      ],
      correct: 2,
      explain: "Кортежи неизменяемы — любая попытка изменить элемент вызывает TypeError."
    }
  ]
});
```

**Шаг 2 — Регистрируем** в `content/stages.js`:
```javascript
// В массиве topics этапа "core":
topics: ["l1_lists", "l1_functions", "l1_dicts", "l1_tuples"]
```

**Шаг 3 — Подключаем** в `index.html`:
```html
<script src="content/core/l1-07-tuples.js"></script>
```

**Шаг 4 — Проверяем:** открываем `dev/selftest.html`, убеждаемся, что тесты зелёные.

Готово. Тема появится в разделе «core» после «Словарей».
