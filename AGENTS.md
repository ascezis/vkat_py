# Инструкция для ИИ-агентов (AGENTS.md)

> **Статус проекта:** v2.1.0 (ветка `main`)  
> **Стек:** HTML5 + CSS3 (Vanilla) + JavaScript (ES6+ Vanilla) + Pyodide (WebAssembly CPython)  
> **Философия:** Zero-Build, Offline-First, No Frameworks, No Bundlers.

---

## 1. Железные архитектурные правила (Hard Constraints)

Любой агент, вносящий изменения в репозиторий, **ОБЯЗАН** строго соблюдать следующие ограничения:

1. **Никаких сборщиков и зависимостей в рантайме (Zero-Build):**
   * **ЗАПРЕЩЕНО:** `npm install`, `package.json` в корне, Webpack, Vite, Rollup, Parcel, React, Vue, Svelte, Tailwind CSS.
   * Проект запускается прямо из папки двойным кликом по `run.bat` или открытием `index.html` в браузере.
   * `Node.js` и `Python` используются **исключительно** для запуска тестов в папке `dev/`.

2. **Офлайн-First (Автономия):**
   * Все шрифты (IBM Plex Sans, IBM Plex Mono), скрипты и WASM-рантайм Pyodide лежат локально в `assets/`.
   * **ЗАПРЕЩЕНО** подключать внешние CDN (Google Fonts, cdnjs, unpkg и т.д.). Тренажёр должен работать на компьютере без интернета.

3. **Изоляция хранилища через `VkatStorage` (`app/storage.js`):**
   * **СТРОГО ЗАПРЕЩЕНЫ** прямые вызовы `localStorage` и `sessionStorage` в коде приложения.
   * Весь доступ к профилям, черновикам и прогрессу идёт **только** через асинхронный API `window.VkatStorage`.
   * Конфликт вкладок исключён: `sessionStorage` хранит активный `id`, а `localStorage` хранит изолированные данные `vkat_p:<id>`.

4. **Честная проверка кода ученика:**
   * Проверка кода выполняется реальным интерпретатором Python через Pyodide (`app/checker.js`).
   * **ЗАПРЕЩЕНО** подменять проверку регулярными выражениями или парсингом строк, если это задание типа `code`.

## 4. Обязательный протокол верификации

Перед формированием **ЛЮБОГО** коммита агент обязан выполнить локально оба набора тестов:

```powershell
node dev/run_js_validation.js
python dev/run_tests.py
```

* **Правило:** Результат должен быть строго `0 ошибок`. Если тесты упали — коммит категорически запрещён до устранения проблемы.

---

## 5. Конвенция коммитов и автоматические релизы

Репозиторий использует автоматическое версионирование на базе **Conventional Commits**:
* `feat: ...` ➔ автоматически поднимает минорную версию (например, `v2.1.0` ➔ `v2.2.0`), создаёт тег, GitHub Release и прикрепляет чистый `vkat_py-vX.Y.Z-standalone.zip`.
* `fix: ...` ➔ автоматически поднимает патч-версию (`v2.1.0` ➔ `v2.1.1`).
* `docs: ...`, `chore: ...`, `test: ...` ➔ не создают новый релиз.
