# Спецификация подсказок по коду (Code Hints & Cheatsheet)

В проекте «вкат.py» синтаксический справочник интегрирован прямо в теорию в виде контекстных подсказок (`CodeHints`).

---

## 1. Как работает система
1. Вся база конструкций хранится в файле `content/cheatsheet.js` в глобальном массиве `window.CHEATSHEET_SECTIONS`.
2. Модуль `app/code-hints.js` при рендере страницы находит блоки кода в теории (`.theory-block-code`).
3. Код в блоке сканируется лексическим анализатором на Python-токены.
4. Токены сопоставляются с триггерами (`triggers`) карточек.
5. Первое вхождение каждого найденного токена оборачивается в интерактивный спан `<span class="hint-token" data-hint="card_id">`.
6. При наведении (задержка 250 мс) или клике всплывает монохромная карточка с подсветкой синтаксиса, описанием и ловушкой.

> **Главное правило для автора тем:**  
> Если ваша тема использует стандартные конструкции (уже добавленные в базу) — **ничего писать не нужно**. Подсказки появятся в примерах кода автоматически!  
> Если тема вводит **новую конструкцию** (например, `try/except`, `import`, `with/open`, `class`) — добавьте соответствующую карточку в `content/cheatsheet.js`.

## 2. Схема карточки подсказки (Item Schema)

Каждая карточка — это JavaScript-объект в массиве `items` соответствующей секции:

```javascript
{
  id: "ctrl_try_except",             // Уникальный snake_case идентификатор
  title: "Обработка ошибок: try / except", // Заголовок (14px, font-weight 600)
  syntax: "try:\n    ...\nexcept ErrorType:\n    ...", // Сигнатура/шаблон вызова
  desc: "Позволяет перехватить ошибку во время работы программы и не дать ей упасть.", // 1-2 предложения (цвет --text-muted)
  code: "try:\n    n = int(\"abc\")\nexcept ValueError:\n    print(\"Не число!\")", // Компактный мини-пример (до 5 строк)
  pitfall: "Никогда не пиши голый except: без типа ошибки — он заглушит даже опечатки в именах переменных и аварийный выход (Ctrl+C).", // Ловушка / грабли (свёрнуто по умолчанию)
  style: "Перехватывай только конкретные типы ошибок, которые реально ожидаешь.", // Рекомендация PEP 8
  triggers: ["try", "except"],       // Массив строковых токенов, активирующих карточку
  topics: ["l1_exceptions"],         // Массив ID тем, где изучается концепция
  tags: ["try", "except", "ошибка", "исключение", "ValueError"] // Ключевые слова
}
```

## 3. Правила для поля `triggers` (КРИТИЧНО)

Анализатор токенов строго различает два типа триггеров:

### А. Одиночные идентификаторы и ключевые слова (Bare Tokens)
- Формат: `"def"`, `"for"`, `"while"`, `"range"`, `"len"`, `"try"`, `"except"`, `"print"`.
- **Срабатывает:** только если слово в коде **НЕ предваряется точкой**.
- Пример: в строке `for i in range(5):` токен `range` откроет карточку `ctrl_range`.
- А в коде `my_obj.range()` триггер `"range"` **НЕ** сработает (так как перед ним стоит точка).

### Б. Методы объектов (Dot Tokens)
- Формат: `".get"`, `".append"`, `".split"`, `".join"`, `".pop"`, `".strip"`.
- **Срабатывает:** только если имя вызывается **через точку** (`obj.method`).
- Пример: в коде `d.get("key")` откроется карточка `dict_get`.
- А в коде `get = 10` триггер `".get"` **НЕ** сработает.

### В. Защита от коллизий
- **Коллизии запрещены:** Один и тот же триггер не может принадлежать двум разным карточкам. Это строго проверяется тестом `dev/run_js_validation.js`.

## 4. Требования к контенту карточки
1. **Компактный код (`code`):** Не более 4–5 строк. Без пустых строк (пустые строки схлопываются). Обязательно комментарий `#` на конце строки с ожидаемым значением/выводом.
2. **Ловушка (`pitfall`):** Самая частая ошибка новичков (почему `int("3.5")` падает, почему `dict[key]` бросает `KeyError`, а `.get()` нет, опасность мутабельных аргументов по умолчанию).
3. **Монохромная безопасность:** Текст в карточке не должен содержать собственных HTML-тегов с инлайн-цветами. Подсветка синтаксиса выполняется автоматически глобальным модулем `window.PythonHighlighter`.

## 5. Существующие секции в `content/cheatsheet.js`
В базе уже выделены 5 секций:
1. `basics` — Базовый синтаксис и типы (`int`, `float`, `str`, `bool`, `type`, `print`, `input`).
2. `ctrl` — Управление потоком (`if`, `elif`, `else`, `for`, `while`, `break`, `continue`, `range`, `def`, `return`).
3. `strings` — Строки и срезы (`len`, `.split`, `.join`, `.strip`, `.replace`, `.find`, `.lower`, `.upper`, срезы `[start:stop:step]`).
4. `collections` — Списки, кортежи, словари, множества (`.append`, `.pop`, `.extend`, `.get`, `.keys`, `.values`, `.items`, `set`, `tuple`).
5. `builtins` — Встроенные функции и полезности (`abs`, `min`, `max`, `sum`, `sorted`, `enumerate`, `zip`, `round`).

Если добавляется тема про **Исключения** — добавьте новую секцию `exceptions` (`try`, `except`, `finally`, `raise`, `ValueError`, `KeyError`, `IndexError`, `TypeError`, `ZeroDivisionError`).  
Если добавляется тема про **Файлы / Модули** — добавьте секцию `modules_io` (`import`, `from`, `with`, `open`, `.read`, `.write`).
