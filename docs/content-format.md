# Спецификация формата учебного контента вкат.py

В данном документе описывается структура курсов, этапов, тем и учебных элементов для авторов контента тренажёра «вкат.py».

---

## 1. Общая архитектура контента

Контент курса организован по трёхзвенной иерархии:
1. **Этап (`stage`)** — крупный блок курса (например, «Начало», «Основной курс»). Описывается в `content/stages.js`.
2. **Тема (`topic`)** — учебная тема (например, «Переменные», «Функции»). Каждый файл в `content/` регистрирует одну или несколько тем.
3. **Элемент (`item`)** — отдельный шаг внутри темы: теория, проверочный вопрос, предсказание вывода, написание кода или поиск ошибки.

Все файлы контента являются чистыми JavaScript-файлами, работающими без шага сборки и подключаемыми через классический тег `<script>`.

---

## 2. Конфигурация этапов (`content/stages.js`)

Файл подключается первым из контентных файлов. Задает массив `window.COURSE_STAGES`:

```javascript
window.COURSE_STAGES = [
  {
    id: "start",
    title: "Начало",
    description: "Одно-два занятия, шесть базовых тем, короткие задания с автопроверкой.",
    topics: [
      "variables",
      "conditions",
      "loops",
      "functions",
      "lists-dicts",
      "strings"
    ],
    finish: {
      title: "Базовый разрыв закрыт!",
      text: "Ты прошёл все ключевые темы..."
    }
  },
  {
    id: "core",
    title: "Основной курс",
    description: "Углублённая практика: теория, предсказание вывода, поиск ошибок.",
    topics: [
      "l1_functions"
    ],
    note: "Пока доступна одна тема, остальные появятся позже",
    finish: {
      title: "Тема «Функции» пройдена!",
      text: "Ты освоил работу с функциями на рабочем уровне."
    }
  }
];
```

### Поля этапа:
- `id` *(string, обязательное)*: уникальный идентификатор этапа.
- `title` *(string, обязательное)*: название для отображения в топбаре, карточках и дереве курса.
- `description` *(string, обязательное)*: краткое описание для стартовой карточки.
- `topics` *(array of string, обязательное)*: список `id` тем в строгом порядке следования.
- `note` *(string, опциональное)*: информационная плашка на карточке этапа.
- `finish` *(object, обязательное)*: `{ title, text }` — заголовок и текст экрана завершения этапа.

---

## 3. Модель темы (`topic`)

Файл темы (например, `content/l1-04-functions.js`) регистрирует тему в глобальном массиве `window.COURSE_TOPICS`:

```javascript
window.COURSE_TOPICS = window.COURSE_TOPICS || [];

window.COURSE_TOPICS.push({
  id: "l1_functions",
  title: "Функции",
  minutes: 60,
  items: [
    /* массив элементов (items) */
  ]
});
```

### Поля темы:
- `id` *(string, обязательное)*: глобально уникальный идентификатор темы.
- `title` *(string, обязательное)*: отображаемое название темы.
- `minutes` *(number, опциональное)*: примерное время прохождения темы.
- `items` *(array of object, обязательное)*: список учебных шагов темы. Допускается поле `tasks` для этапа «Начало» (нормализуется автоматически).

---

## 4. Модели учебных элементов (`items`)

Общие поля для всех элементов:
- `id` *(string, обязательное)*: глобально уникальный и неизменяемый идентификатор (например, `l1_fn_t1`, `l1_fn_c1`).
- `type` *(string, опциональное)*: тип элемента: `'theory' | 'quiz' | 'predict' | 'code'`. Если не указан, считается `'code'`.
- `title` *(string, обязательное)*: заголовок шага.

---

### 4.1. Теория (`type: "theory"`)

Страница для чтения, раскрывающаяся на всю ширину рабочей области. Не входит в счётчик обязательных заданий для прогресс-бара, но получает отметку `✓` в дереве и шагах.

```javascript
{
  id: "l1_fn_t1",
  type: "theory",
  title: "Функция: определение и вызов",
  blocks: [
    {
      type: "p",
      html: "Функция — это поименованный блок кода..."
    },
    {
      type: "code",
      code: "def hello():\n    print(\"Привет!\")\n\nhello()",
      output: "Привет!"
    },
    {
      type: "list",
      items: [
        "Первый пункт списка",
        "Второй пункт с <code>кодом</code>"
      ]
    },
    {
      type: "table",
      head: ["Колонка 1", "Колонка 2"],
      rows: [
        ["Значение A", "Значение B"],
        ["Значение C", "Значение D"]
      ]
    },
    {
      type: "note",
      html: "Важная мысль или предостережение в рамке."
    }
  ]
}
```

---

### 4.2. Проверочный вопрос (`type: "quiz"`)

Интерактивный тест с выбором одного варианта ответа.
- Неверный ответ показывает понятное сообщение и позволяет попробовать снова.
- Верный ответ засчитывает элемент, показывает блок `explain` и кнопку перехода дальше.

```javascript
{
  id: "l1_fn_q1",
  type: "quiz",
  title: "Функция создана, но не вызвана",
  question: "В программе есть только эти строки. Что произойдёт при запуске?",
  code: "def hello():\n    print(\"Привет\")", // опционально
  options: [
    "Выведется «Привет»",
    "Ничего не выведется",
    "Будет NameError",
    "Будет SyntaxError"
  ],
  correct: 1, // 0-индексированный номер правильного ответа
  explain: "Строка def только запоминает функцию. Код внутри выполняется при вызове hello()."
}
```

---

### 4.3. Предсказание вывода (`type: "predict"`)

Ученик видит код (только для чтения) и поле для ввода ожидаемого результата работы программы:
- После отправки код запускается по-настоящему в Pyodide.
- Показывается фактический вывод, совпадение с ответом ученика и текст разбора `explain`.
- **Элемент засчитывается после первой отправки (неверный ответ не блокирует прохождение).**

```javascript
{
  id: "l1_fn_p1",
  type: "predict",
  title: "Сложение результатов return",
  explanation: [
    "Посмотри на код программы и определи, какой вывод появится в консоли при запуске."
  ],
  code: "def square(x):\n    return x * x\n\nprint(square(2) + square(3))",
  expectedOutput: "13",
  explain: "square(2) возвращает 4, square(3) возвращает 9. 4 + 9 = 13."
}
```

### 4.4. Задание на написание кода (`type: "code"`)

Полноценное задание в редакторе с проверкой на WebAssembly/Pyodide.

```javascript
{
  id: "l1_fn_c4",
  type: "code",
  tier: "main",                  // 'warmup' | 'main' | 'star'
  kind: "fix",                   // опционально: 'fix' (найди ошибку)
  optional: false,               // true для звёздочек (star)
  title: "Функция max_of_two без max()",
  explanation: [
    "Сравни два числа с помощью условного оператора if и верни большее."
  ],
  assignment: "Напиши функцию max_of_two(a, b), которая возвращает большее из двух чисел...",
  starterCode: "# Напиши функцию max_of_two(a, b) без max()\n",
  expectedOutput: "5",           // опционально (если нужен точный вывод программы)
  astRequirements: {
    require_def: true,
    require_return: true,
    require_if: true,
    forbid_calls: ["max", "min", "sorted"], // запрещённые вызовы
    forbid_methods: ["sort"],               // запрещённые методы
    require_calls: ["draw_line"]            // обязательный вызов функции
  },
  tests: [
    { call: "max_of_two(3, 5)", returns: 5 },
    { call: "max_of_two(9, 2)", returns: 9 },
    { call: "max_of_two(4, 4)", returns: 4 },
    { call: "max_of_two(-1, -5)", returns: -1, hidden: true }
  ],
  hints: [
    "Сравни a > b: если условие истинно, верни a, иначе верни b.",
    { code: "def max_of_two(a, b):\n    if a > b:\n        return ___\n    return ___" },
    { code: "def max_of_two(a, b):\n    if a > b:\n        return a\n    return b" }
  ],
  improveTip: "После return в if блок else писать не обязательно.",
  successMessage: "Поиск максимума через условия работает без встроенных функций!"
}
```

#### Спецификация проверочных тестов `tests[]`:
Каждый тест задаётся объектом:
- `call` *(string)*: строка вызова на Python, исполняемая в пространстве имён решения ученика (`_user_ns`).
- `returns` *(any)*: ожидаемое возвращаемое значение.
  - `bool` сравнивается строго на тип `bool`.
  - числа сравниваются математически (`2 == 2.0`).
  - строки сравниваются посимвольно.
- `stdout` *(string)*: ожидаемый перехваченный вывод именно этого вызова (с нормализацией пробелов).
- `hidden` *(boolean)*: если `true`, при провале вызов не раскрывается ученику, а выводится подсказка: «Не пройден дополнительный тест. Проверь граничные случаи: ноль, пустая строка, отрицательные числа.»

---

## 5. Правила авторинга контента

1. **Тон текста:** обращение строго на «ты», спокойный, уважительный, без восклицательных знаков, сюсюканья и эмодзи.
2. **Точность формулировок:** в условии задания всегда однозначно указываются имена функций, имена параметров и точный формат вывода.
3. **Лестница помощи:** для каждого задания на код пишется 3 подсказки:
   - Подсказка 1: словесная идея решения без готового кода.
   - Подсказка 2: шаблон решения с пропусками `___`.
   - Подсказка 3: готовое эталонное решение.
4. **Изоляция автотестов:** эталоны и заведомо ошибочные решения хранятся в папке `dev/selftest/`, чтобы исключить разглашение решений в браузере ученика.
