# Спецификация создания тем: вкат.py

Каждая тема — это массив учебных элементов (`items`), выстроенных в строгой методической последовательности.

---

## 1. Педагогический ритм темы
Оптимальный размер темы — **16–20 элементов**:
- **Теория (theory):** 4–6 блоков. Короткие, сфокусированные на одной мысли порции.
- **Квиз (quiz):** 3–4 шага сразу после теории для быстрой проверки базового понимания концепции.
- **Предсказание вывода (predict):** 2–3 шага на чтение чужого кода с мысленным выполнением.
- **Исправление багов (fix):** 1–2 шага на поиск и исправление типовой ошибки.
- **Задачи на написание кода (code):** 6–8 задач с нарастанием сложности.
- **Необязательные задачи повышенной сложности (звёздочки):** 1–2 шага (`optional: true` или `tier: "star"`), не блокирующие продвижение по курсу.

---

## 2. Справочник типов элементов (`type`)

### 2.1. `theory` (Теория)
Теоретический блок состоит из массива `blocks`:
```javascript
{
  type: "theory",
  id: "l1_topic_t1",
  title: "Заголовок экрана теории",
  blocks: [
    { type: "p", text: "Объяснение концепции. Пиши живым языком, выделяя важное." },
    { 
      type: "code", 
      code: "def greet(name):\n    return f\"Привет, {name}!\"\n\nprint(greet('Аня'))",
      output: "Привет, Аня!" // опционально: ожидаемый вывод в терминале под кодом
    },
    { type: "p", text: "Комментарий к примеру или разбор механики." },
    { type: "tip", text: "Главное правило или совет, выделяемый плашкой с левой полосой." }
  ]
}
```
*Поддерживаемые типы блоков в `blocks`:*
- `p` — абзац текста.
- `code` — блок кода. Поддерживает поле `output` (серая плашка снизу с результатом выполнения). В коде теории **автоматически работают подсказки CodeHints**.
- `tip` — важное правило или акцент (рамка с акцентной левой полосой).
- `list` — маркированный список (`items: ["пункт 1", "пункт 2"]`).

### 2.2. `quiz` (Квиз с вариантами ответа)
Проверка на понимание механики:
```javascript
{
  type: "quiz",
  id: "l1_topic_q1",
  title: "Что вернёт вызов?",
  question: "Какое значение вернёт следующий фрагмент кода?",
  code: "x = [1, 2, 3]\nprint(x.pop())", // опционально
  options: [
    "[1, 2]",
    "3",
    "None",
    "IndexError"
  ],
  answer: 1, // 0-based индекс правильного ответа (здесь "3")
  explanation: "Метод .pop() удаляет последний элемент из списка и возвращает именно его (значение 3)."
}
```

---

### 2.3. `predict` (Предсказание вывода в консоль)
Ученик читает код и вводит точный вывод программы без её запуска:
```javascript
{
  type: "predict",
  id: "l1_topic_p1",
  title: "Что выведет программа?",
  code: "d = {'a': 1, 'b': 2}\nd['a'] = 10\nprint(d['a'], len(d))",
  expectedOutput: "10 2", // строковое совпадение с точностью до пробелов/переводов строк
  explanation: "Ключ 'a' перезаписался со значением 10, а количество ключей в словаре осталось равным 2."
}
```

---

### 2.4. `fix` (Поиск и исправление ошибки)
Даётся неработающий или ошибочный код. Ученик должен внести минимальное точечное исправление:
```javascript
{
  type: "fix",
  id: "l1_topic_f1",
  title: "Исправь баг: функция ничего не возвращает",
  prompt: "Функция должна возвращать удвоенное число, но сейчас выводит его через print. Исправь код, заменив print на return.",
  initialCode: "def double(x):\n    print(x * 2)\n\nres = double(5) + 1",
  tests: [
    { call: "double(5)", returns: 10 },
    { call: "double(0)", returns: 0 },
    { call: "double(-3)", returns: -6, hidden: true }
  ],
  expectedOutput: "11" // если код также что-то печатает при запуске
}
```

---

### 2.5. `code` (Самостоятельное написание кода)
Полноценная задача с автопроверкой через тестовые вызовы и AST-анализатор:
```javascript
{
  type: "code",
  id: "l1_topic_c1",
  title: "Напиши функцию подсчёта",
  prompt: "Напиши функцию `count_positive(numbers)`, которая принимает список чисел и возвращает количество строго положительных элементов.",
  initialCode: "def count_positive(numbers):\n    # твой код здесь\n    pass\n\nprint(count_positive([1, -2, 3, 0, 5]))",
  astRequirements: {
    require_def: true,        // обязательно объявить функцию через def
    require_return: true,     // обязательно вернуть результат через return
    require_for: true,        // обязательно использовать цикл for
    forbid_calls: ["sum"]     // запретить готовые функции-читерства (опционально)
  },
  tests: [
    { call: "count_positive([1, -2, 3, 0, 5])", returns: 3 },
    { call: "count_positive([])", returns: 0 },
    { call: "count_positive([-1, -2, -3])", returns: 0 },
    { call: "count_positive([10, 20, 30])", returns: 3, hidden: true }
  ]
}
```

#### Возможности AST-анализатора (`astRequirements`):
- `require_def: true` — требует `def`
- `require_return: true` — требует `return`
- `require_for: true` — требует цикл `for`
- `require_while: true` — требует цикл `while`
- `require_loop: true` — требует любой цикл (`for` или `while`)
- `require_if: true` — требует ветвление `if`
- `require_calls: ["func_name"]` — требует вызов конкретной функции (например, вспомогательной)
- `forbid_calls: ["max", "sum", "sorted"]` — запрещает вызов читерских функций
- `forbid_methods: ["count", "sort"]` — запрещает вызов определённых методов

#### Типы проверок в тестах (`tests`):
- `returns: <значение>` — проверка возвращаемого значения функции при вызове `call`.
- `stdout: <строка>` — проверка вывода в консоль (для функций, которые делают `print`).
- `hidden: true` — скрытый тест (не виден в списке тестов ученика до прохождения).

## 3. Правила оформления и стиль
1. **Уникальность ID:** Все ID элементов в рамках всего проекта должны быть уникальными (формат: `l1_<краткая_тема>_<тип><номер>`, например `l1_str_t1`, `l1_str_c3`).
2. **Русский язык:** Все пояснения, сообщения и задачи — на чистом, понятном русском языке.
3. **Строгий монохром:** Никаких эмодзи в текстах интерфейса, только четкие формулировки.
4. **Безопасность тестов:** Не используйте бесконечные циклы, тяжёлые вычисления или нелокальные импорты.
