# вкат.py — Спецификация системы профилей (PROFILE_SYSTEM)

Документ описывает архитектуру изолированного многопользовательского хранения прогресса на одном устройстве, контракт модуля `app/storage.js`, экраны входа и смены профиля, а также правила миграции устаревших данных.

---

## 1. Назначение и контекст

### Проблема
Тренажёр используется в компьютерных классах школ программирования. За одним и тем же компьютером и в одном браузере по очереди занимаются разные ученики:
- Ученик А решает задания темы «Функции».
- На следующем уроке за тот же компьютер садится ученик Б и видит уже решённые чужие задания или перезаписывает чужой черновик.
- Если ученик открывает вторую вкладку браузера, несогласованные ключи `localStorage` затирают прогресс.

### Цель
Обеспечить полную изоляцию прогресса, черновиков кода и позиции каждого ученика без усложнения проекта (сохраняя автономность, работу без сервера, без сборки и без интернета).

## 2. Схема хранения данных

### 2.1. `localStorage` (постоянное хранилище на компьютере)

| Ключ | Тип | Описание |
| :--- | :--- | :--- |
| `vkat_profiles` | `Array<ProfileMeta>` | Реестр профилей на данном компьютере |
| `vkat_last_profile` | `string` (id) | Подсказка для интерфейса (кто входил последним) |
| `vkat_p:<id>` | `ProfileData` | Полный снимок данных конкретного профиля (одним JSON-объектом) |
| `vkat_legacy_backup` | `string` | Неизменяемая резервная копия старого плоского хранилища до миграции |

#### Формат `ProfileMeta` (метаданные реестра):
```typescript
interface ProfileMeta {
  id: string;          // Случайный уникальный идентификатор (8 символов, например "k9f2x7a1")
  name: string;        // Имя ученика для отображения (1-30 символов)
  pinHash?: string;    // SHA-256 хэш 4-значного PIN-кода (если включена защита от соседа)
  created: number;     // Unix timestamp создания
  lastUsed: number;    // Unix timestamp последнего открытия
}
```

#### Формат `ProfileData` (`vkat_p:<id>`):
```typescript
interface ProfileData {
  schema: 2;                           // Версия схемы данных профиля
  completed: string[];                 // Массив ID выполненных заданий и прочитанной теории
  drafts: Record<string, string>;      // Словарь черновиков кода: { [taskId]: "код ученика" }
  position: {                          // Семантическая позиция вместо числовых индексов
    topicId: string;                   // ID текущей темы (например, "l1_functions")
    itemId: string;                    // ID текущего шага (например, "l1_fn_c1")
  };
  updated: number;                     // Timestamp последнего сохранения
}
```

> [!IMPORTANT]
> **Почему позиция хранится как `{ topicId, itemId }`:**  
> Индексы `topicIndex` и `taskIndex` ломаются при добавлении новой темы в середину курса или добавлении шага в тему. Хранение по строковым ID полностью устойчиво к любым изменениям программы курса.

### 2.2. `sessionStorage` (изоляция на уровне конкретной вкладки)

| Ключ | Тип | Описание |
| :--- | :--- | :--- |
| `vkat_active_profile` | `string` (id) | Идентификатор профиля, активного **в данной вкладке** |

- Если ученик А открыл профиль в Вкладке 1, а ученик Б открыл другой профиль во Вкладке 2 — вкладки пишут в разные ключи `vkat_p:<id_A>` и `vkat_p:<id_B>`.
- Конфликт перезаписи исключён на аппаратном уровне изоляции сессий браузера.

## 3. Модуль хранилища (`app/storage.js`)

Весь доступ к хранилищу изолирован внутри модуля `window.VkatStorage`. В `app/app.js` и других частях приложения **прямые вызовы `localStorage` и `sessionStorage` запрещены**.

Интерфейс спроектирован полностью асинхронным (`Promise`). Сейчас под капотом работает `LocalAdapter` (`localStorage` / `sessionStorage`). При появлении сервера в будущем подключение `RemoteAdapter` произойдёт без правки интерфейса и логики приложения.

### Публичный контракт API:

```javascript
window.VkatStorage = {
  // === Управление реестром профилей ===
  listProfiles(): Promise<ProfileMeta[]>,
  createProfile(name: string, pin?: string): Promise<ProfileMeta>,
  deleteProfile(id: string): Promise<void>,
  
  // === Авторизация и переключение ===
  selectProfile(id: string, pin?: string): Promise<ProfileData>,
  getActiveProfile(): ProfileMeta | null,
  clearActiveProfile(): void,
  
  // === Чтение и запись данных активного профиля ===
  load(): Promise<ProfileData>,
  save(patch: Partial<ProfileData>): Promise<void>,
  saveDraftDebounced(taskId: string, code: string): void,
  flushSync(): void, // Немедленный синхронный сброс буфера перед выходом/сменой

  // === Миграция, резервные копии и перенос ===
  checkLegacyData(): boolean,
  migrateLegacyToProfile(targetProfileId: string): Promise<void>,
  exportProfile(id: string): Promise<void>, // Скачивание vkat-profile-<name>-<date>.json
  importProfile(fileJsonString: string): Promise<ProfileMeta>,
  resetAll(): Promise<void> // Защищённый полный сброс устройства
};
```

### Защита от потери черновиков (Debounce + Flush):
- При наборе текста в редакторе вызывается `saveDraftDebounced(taskId, code)` с задержкой **500 мс**, чтобы не сериализовать весь профиль на каждое нажатие клавиши.
- Перед любой смене профиля, выходе на экран выбора или по событию `window.addEventListener('beforeunload', ...)` вызывается `flushSync()`, гарантирующий немедленную запись текущего состояния в `localStorage`.

## 4. Пользовательский интерфейс и сценарии (User Flow)

### 4.1. Первый запуск (профилей нет)
1. Пользователь видит экран `screen-profiles` в режиме создания:
   - Заголовок: `вкат.py / добро пожаловать`
   - Поле ввода имени: `Как тебя зовут?`
   - Опциональный PIN: 4 цифры (с подсказкой: «чтобы сосед случайно не зашёл в твой профиль»).
2. Если обнаружены старые плоские ключи `vkat_completed_tasks`, появляется чекбокс:
   `☑ Перенести сохранённый прогресс с этого компьютера` (активен по умолчанию).
3. По кнопке «Создать и начать» создаётся профиль, переносятся данные, ID пишется в `sessionStorage.vkat_active_profile`, открывается экран этапов курса.

### 4.2. Повторный запуск (профили созданы)
1. Если в текущей вкладке `sessionStorage.vkat_active_profile` пуст:
   - Показывается экран `screen-profiles` («Кто ты?»).
   - Сетка карточек с именами учеников, аватарами с первой буквой имени и текущим прогрессом (например, `этап 1 · 18/26`).
   - Карточка профиля из `vkat_last_profile` визуально выделена (бейдж «Последний вход»).
   - Кнопка `+ Новый профиль`.
   - Вспомогательная кнопка «Импорт из файла» внизу экрана.
2. Клик по карточке:
   - Если PIN не задан — мгновенный вход.
   - Если PIN задан — всплывает лаконичный модальный ввод 4 цифр. При правильном вводе — вход в профиль.

### 4.3. Смена профиля на уроке
1. В верхнем топбаре приложения отображается бейдж:  
   `[ Артём · сменить ]`
2. При нажатии на кнопку «сменить»:
   - Вызывается `VkatStorage.flushSync()` (сохраняются несохранённые символы редактора).
   - Очищается `sessionStorage.removeItem('vkat_active_profile')`.
   - Вызывается `window.location.reload()`.
3. Страница перезагружается с чистой памятью (без мусора от предыдущего сеанса) и встречает следующего ученика экраном выбора профиля.

### 4.4. Защита от случайного удаления
- Кнопка удаления профиля на карточке требует подтверждения (`confirm`).
- Полный сброс всех профилей устройства скрыт за долгим нажатием (4 секунды) на номер версии в подвале стартового экрана или специальной комбинацией клавиш, исключающей случайный клик ребёнка.

## 5. Миграция со старой схемы (Legacy)

Старая схема хранила данные в виде разрозненных ключей:
- `vkat_completed_tasks`: `["var_intro", ...]`
- `vkat_code_drafts`: `{"var_intro": "..."}`
- `vkat_current_position`: `{"topicIndex": 0, "taskIndex": 2}`
- `vkat_schema`: `"2"`

### Алгоритм миграции:
1. Метод `checkLegacyData()` проверяет наличие ключа `vkat_completed_tasks` при отсутствии `vkat_profiles`.
2. Создаётся резервный неизменяемый слепок в `vkat_legacy_backup`.
3. Создаётся профиль (например, с именем по умолчанию или введённым учеником).
4. `topicIndex` и `taskIndex` преобразуются в стабильные `{ topicId, itemId }` через обход реестра `COURSE_STAGES`.
5. Сформированный объект записывается в `vkat_p:<new_id>`.
6. Старые ключи удаляются из `localStorage` во избежание повторной миграции.

## 6. Межвкладочная синхронизация

Если один и тот же профиль открыт в двух вкладках одновременно:
- Модуль `storage.js` слушает системное событие `window.addEventListener('storage', (e) => ...)`:
  - При изменении ключа `vkat_p:<active_id>` из другой вкладки, в текущей вкладке обновляется локальный кэш выполненных заданий.
  - Если на экране был открыт тот же шаг, показывается ненавязчивый индикатор: `Прогресс обновлён из соседней вкладки`.

## 7. Чеклист приёмочного тестирования (QA Scenarios)

1. **Базовое разделение:**
   - Ученик 1 создаёт профиль, решает 4 задачи темы «Переменные».
   - Переключается на экран профилей, Ученик 2 создаёт профиль и решает 8 задач.
   - Возврат в профиль Ученика 1: в прогрессе ровно 4 решённых задачи, сохранены именно его черновики.
2. **Параллельные вкладки:**
   - В Вкладке 1 открыт Профиль А.
   - В Вкладке 2 открыт Профиль Б.
   - Решение задач в Вкладке 1 не меняет прогресс и черновики в Вкладке 2.
3. **Безопасность черновиков:**
   - Набор неполного кода в редакторе и мгновенное нажатие «сменить профиль» не теряет ни одного введённого символа (проверка `flushSync`).
4. **Устойчивость к реструктуризации контента:**
   - Профиль с сохранённой позицией корректно открывается даже при добавлении/удалении шагов (fallback на первый валидный шаг темы).
5. **Экспорт и импорт:**
   - Экспорт профиля в `.json`, удаление профиля из браузера, импорт из файла — 100% прогресса и черновиков восстанавливаются.
