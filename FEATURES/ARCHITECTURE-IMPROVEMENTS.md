# Концепция развития архитектуры: Модульность, Пет-проекты и Контрольные

> **Статус документа:** Концепт / Архитектурное предложение  
> **Дата:** Октябрь 2026  
> **Цель:** Обеспечить масштабирование платформы от тренажёра «ликвидации разрывов» до полноценной легковесной учебной среды без роста технического долга и без добавления сборщиков (Zero-Build Vanilla Stack).

---

## 1. Контекст: Эволюция продукта

Изначально проект создавался как монолитный офлайн-тренажёр «вкат.py» для быстрого входа учеников, пропустивших первые уроки. 

В процессе развития платформа органично переросла эту рамку благодаря ключевым преимуществам:
1. **Абсолютно автономный рантайм:** Настоящий CPython в браузере (Pyodide WebAssembly).
2. **Нулевой технический долг:** Отсутствие сборщиков (Webpack, Vite, Rollup) и фреймворков исключает старение зависимостей и поломки через годы.
3. **Локальная многопользовательская изоляция:** Система профилей (`VkatStorage`), SHA-256 PIN-коды и сессионные вкладки.

Следующий шаг эволюции — превращение в **модульную учебную экосистему**, включающую:
* Базовый разрыв («Начало»).
* Основной курс (углубленные темы).
* **Интерактивные мини-пет-проекты** (строительные леса с живым откликом).
* **Контрольные срезы и аттестации** (с выгрузкой по `CONNECT-PROTOCOL.md`).

---

## 2. Архитектурный вызов: Как расти без раздувания (Zero-Bloat)

При текущей архитектуре:
* Каждый новый файл темы требует ручного добавления `<script>` в `index.html`.
* Все курсы и карточки загружаются в оперативную память браузера одновременно на старте.
* При добавлении новых форматов (например, холст для игр) файл `app/app.js` рискует разрастись огромными блоками `if/else`.

**Задача:** Обеспечить модульность, ленивую загрузку и расширяемость, сохранив работу с двойного клика по `run.bat` без Node.js и npm в рантайме.

### Улучшение 1. Манифест курсов и ленивая загрузка (Dynamic Module Loader)

Вместо фиксированных скриптов в `index.html` создаётся легковесный манифест курсов:

#### Структура `content/manifest.js`:
```javascript
window.COURSE_CATALOG = [
  {
    id: "vkat_start",
    title: "Вкат: Ликвидация разрыва",
    category: "basics",
    scripts: [
      "content/stages.js",
      "content/01-variables.js",
      "content/02-conditions.js",
      "content/03-loops.js",
      "content/04-functions.js",
      "content/05-lists-dicts.js",
      "content/06-strings.js"
    ]
  },
  {
    id: "core_advanced",
    title: "Основной курс",
    category: "core",
    scripts: [
      "content/l1-03-lists.js",
      "content/l1-04-functions.js",
      "content/l1-05-dicts.js"
    ]
  },
  {
    id: "pet_chess",
    title: "Пет-проект: Шахматный движок",
    category: "projects",
    customRenderer: "canvas_board",
    scripts: [
      "content/projects/chess/engine.js",
      "content/projects/chess/tasks.js"
    ]
  }
];
```

#### Механизм динамической подгрузки (`app/loader.js`):
Браузер подгружает файлы только выбранного курса:
```javascript
async function loadCoursePackage(courseId) {
  const course = window.COURSE_CATALOG.find(c => c.id === courseId);
  if (!course) throw new Error("Курс не найден");

  for (const src of course.scripts) {
    if (!document.querySelector(`script[src="${src}"]`)) {
      await new Promise((resolve, reject) => {
        const script = document.createElement('script');
        script.src = src;
        script.onload = resolve;
        script.onerror = () => reject(new Error(`Не удалось загрузить ${src}`));
        document.body.appendChild(script);
      });
    }
  }
}
```

* **Результат:** `index.html` остаётся ультра-чистым, страница стартует мгновенно, не перегружая браузер.

### Улучшение 2. Пакетная структура репозитория

Контент организуется в изолированные каталоги:

```text
content/
├── manifest.js               # Общий реестр всех доступных пакетов
├── courses/
│   ├── 01-start/             # Базовые 6 тем
│   └── 02-core/              # Углубленные темы (списки, функции, словари, ООП)
├── projects/                 # Интерактивные мини-петы
│   ├── chess/                # Шахматы: заготовка логики + задачи
│   ├── roguelike/            # Лабиринт и столкновения
│   └── battleship/           # Морской бой
└── exams/                    # Контрольные срезы и срезы знаний
    ├── midterm-1.js
    └── oop-final.js
```

Каждый каталог — автономная единица. Их можно подключать или отключать изменением одной строки в `manifest.js`.

### Улучшение 3. Реестр карточек (Pluggable Renderers)

Декомпозиция рендера карточек через интерфейсный реестр:

```javascript
const ItemRenderers = {
  theory: renderTheoryView,
  quiz: renderQuizView,
  predict: renderPredictView,
  code: renderCodeView,
  // Новые типы:
  game_scaffold: renderGameScaffoldView, // Пет-проекты с визуализатором
  exam_task: renderExamTaskView          // Задачи контрольной без подсказок
};

function renderTask(item) {
  const renderer = ItemRenderers[item.type] || ItemRenderers.code;
  renderer(item);
}
```

Ядро `app.js` не знает подробностей того, как рисуется шахматная доска или лабиринт — оно просто делегирует рендер специализированному обработчику.

### Улучшение 4. Архитектура интерактивных пет-проектов (Scaffolded Games)

#### Концепция:
Вместо стресса от «чистого листа» ученику даётся живой полуготовый проект. 

```
┌─────────────────────────────────┬─────────────────────────────────┐
│     Левая панель: Интерактив    │      Правая панель: Код         │
│                                 │                                 │
│  [ Визуальное поле игры ]       │  def can_knight_move(x1, y1,   │
│  ┌───┬───┬───┐                  │                     x2, y2):    │
│  │   │ ♞ │   │                  │      dx = abs(x2 - x1)          │
│  ├───┼───┼───┤                  │      dy = abs(y2 - y1)          │
│  │   │   │   │                  │      # ТВОЙ КОД ЗДЕСЬ:          │
│  ├───┼───┼───┤                  │      return ...                 │
│  │ * │   │ * │                  │                                 │
│  └───┴───┴───┘                  │  [ ▶ Проверить ход коня ]       │
│  Зелёным подсвечены ходы        │                                 │
└─────────────────────────────────┴─────────────────────────────────┘
```

#### Механика связи Python и Canvas:
1. Заготовка игры содержит базовый цикл и модель данных на Python.
2. Ученик пишет тело ключевой функции (например, валидация хода, расчёт урона, поиск пути).
3. При нажатии «Проверить» Pyodide выполняет код и возвращает JSON-состояние доски в JS.
4. Браузер перерисовывает `<canvas>` или ASCII-сетку — конь оживает прямо на глазах ученика.

### Улучшение 5. Модуль контрольных работ (Exam Mode)

Специализированный режим для проверки знаний:

1. **Ограничения интерфейса:**
   * Полностью скрыты кнопки подсказок (`#hint-toggle`) и подсказок «как сделать лучше».
   * Запрещён переход к ответам до завершения всего блока.
   * Опциональный встроенный таймер (например, 45 минут).
2. **Сдача работы и телеметрия:**
   * По кнопке «Завершить контрольную» формируется пакет снимков по спецификации [`CONNECT-PROTOCOL.md`](./CONNECT-PROTOCOL.md).
   * Результат либо скачивается файлом `exam-<name>-<date>.vkat`, либо моментально отправляется на вебхук преподавателя (Yandex Cloud Function / Google Sheets).

## 4. Дорожная карта реализации

| Этап | Задача | Затрагиваемые компоненты | Риск |
| :--- | :--- | :--- | :--- |
| **Этап 1** | Выделение реестра рендереров карточек (`ItemRenderers`) | `app/app.js` | Минимальный (рефакторинг рендера) |
| **Этап 2** | Внедрение `content/manifest.js` и динамической подгрузки | `app/loader.js`, `index.html` | Низкий (сохранение обратной совместимости) |
| **Этап 3** | Пилотный пет-проект «Лабиринт / Roguelike» (текстовый) | `content/projects/roguelike/` | Низкий |
| **Этап 4** | Режим контрольной (`exam_task`) + интеграция с `CONNECT-PROTOCOL` | `content/exams/`, `app/storage.js` | Низкий |
| **Этап 5** | Визуальный Canvas-рендерер для шахмат / 2D игр | `app/renderers/canvas.js` | Средний (UI/UX проработка) |

## 5. Главный принцип

> **Любое расширение должно работать без интернета и без сборки.**  
> Если новый модуль требует `npm install` или ломает запуск по `run.bat` — он отвергается. Сила платформы — в её стопроцентной автономности и простоте.
