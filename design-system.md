# Дизайн-система — «вкат.py»

Референс для реализации. Один экран-образец: `lesson-mockup.html` (тема «циклы»).
Ниже — все значения, которые иначе будут додуманы на глаз и разойдутся между экранами.

## Принцип

Эстетика редактора кода / терминала, а не обучающей платформы. Строго чёрно-белая:
никаких цветовых акцентов вообще, даже для «ошибки» или «успеха». Состояния различаются
только через вес линии, заливку, символ (✓ / ×) и текст — никогда через цвет.

## Цвет

| Токен | Hex | Назначение |
|---|---|---|
| `--bg` | `#0a0a0a` | Фон страницы |
| `--bg-panel` | `#121212` | Панели (редактор кода) |
| `--bg-panel-alt` | `#0d0d0d` | Вложенные элементы (inline-код) |
| `--text` | `#ececec` | Основной текст |
| `--text-muted` | `#7a7a7a` | Вторичный текст, вывод консоли |
| `--text-dim` | `#4d4d4d` | Лейблы, метки, декоративный текст |
| `--border` | `#2a2a2a` | Обычные разделители |
| `--border-strong` | `#454545` | Акцентные границы (фокус, левая линия у console) |
| `--fill` / `--fill-text` | `#ececec` / `#0a0a0a` | Инверсия — единственный способ выделить (кнопка, успех) |

Правило: **не добавлять новые оттенки**. Если кажется, что не хватает цвета для акцента —
решение через инверсию (тёмное на светлом) или толщину линии, не через новый hex.

## Типографика

- **IBM Plex Sans** — интерфейс, объяснения, заголовки. Вес 400/500/600.
- **IBM Plex Mono** — код, лейблы, счётчики шагов, breadcrumb, вывод программы.

Подключение (доступно офлайн, если зашить шрифты в файлы — см. раздел «Offline» ниже):
```html
<link href="https://fonts.googleapis.com/css2?family=IBM+Plex+Sans:wght@400;500;600&family=IBM+Plex+Mono:wght@400;500;600&display=swap" rel="stylesheet">
```

Правила:
- Заголовок урока — 22px / 600.
- Тело текста — 15px / 400, `line-height: 1.6`.
- Код и всё, что относится к «системе» (лейблы, метки) — всегда Mono, 12–14px.
- Никогда не использовать ALL CAPS для лейблов — только `--text-dim` + маленький размер.
- Длина строки объяснений — не больше ~55 символов (`max-width: 52ch`).

## Layout

Двухпанельная сетка, как в IDE: слева объяснение, справа редактор.

```
+----------------------------------------------------+
| вкат·py                  циклы · задание 3 из 6     |  ← topbar
+------------------------------------------------------+ ← progress line (1px)
|  ОБЪЯСНЕНИЕ            |  ТВОЙ КОД                    |
|  заголовок             |  [ textarea, моноширинный ]  |
|  текст + пример         |                              |
|  ЗАДАНИЕ                | [подсказка]      [Проверить] |
|  формулировка           |  РЕЗУЛЬТАТ: ✓/× + пояснение  |
|                          |  КАК СДЕЛАТЬ ЛУЧШЕ: ...      |
+------------------------------------------------------+
| python · до классов        ● ● ● ○ ○ ○     шаг 3 / 6  |  ← bottombar
+----------------------------------------------------+
```

- Выравнивание — везде по левому краю. Никакой центровки текста.
- Панели разделены **одной тонкой линией** (`1px solid var(--border)`), не тенью.
- Никаких скруглений углов, теней, градиентов — вообще ни у одного элемента.
- На узких экранах (`<860px`) панели складываются в одну колонку.

## Прогресс и состояния

- **Прогресс курса** — тонкая линия (1px) вверху экрана, заполняется слева направо
  заливкой `--text`. Без процентов и цифр поверх.
- **Шаги внутри урока** — маленькие точки (5×5px) внизу экрана, пройденные — залиты,
  оставшиеся — контур `--border-strong`. Без нумерации кружков (01/02/03) — просто точки.
- **Успех** — символ `✓`, заголовок «Задание засчитано», без анимации-праздника.
  Максимум — плавная смена состояния за 150–200ms.
- **Ошибка** — символ `×`, тем же начертанием, что и `✓` (не жирнее, не крупнее).
  Пояснение — текстом, без drama.
- **Замечание по стилю/чистоте кода** — отдельный блок «Как сделать лучше» с пунктирной
  рамкой (`border: 1px dashed`), **не блокирует** переход дальше. Это единственный
  элемент с непривычным стилем рамки — намеренно, чтобы визуально читаться как
  необязательный совет, а не как ошибка.

## Кнопки и интерактивные элементы

- Основная кнопка (`Проверить`) — инверсия: светлая заливка на тёмном фоне. Без стрелок
  в тексте кнопки, без иконок — только глагол действия.
- Второстепенное действие (`показать подсказку`) — текстовая ссылка с подчёркиванием,
  без рамки и фона.
- Фокус (`:focus-visible`) — обязательно видимый контур (`outline: 2px solid var(--text)`),
  не убирать ради эстетики.

## Тон текста

- Обращение на «ты», нейтрально-простой язык — без сюсюканья и без канцелярита.
- Примеры — через бытовые/игровые ситуации (очки в игре, шаги, счётчики), не абстрактные
  «рассмотрим множество X».
- Ошибка объясняется как факт («Вывод не совпадает: ожидалось …, получено …»), без
  извинений и без «ой».

## Offline-требование (важно для standalone)

Средa запуска — флешка, без интернета. Значит:
- Шрифты IBM Plex Sans/Mono должны быть **скачаны и подключены локально**
  (`@font-face` + файлы `.woff2` рядом), а не через `fonts.googleapis.com` в финальной сборке.
  В макете сейчас — CDN-ссылка, только для просмотра дизайна в браузере, не для сборки.
- Всё остальное (CSS/JS) — уже инлайн/локально, зависимостей от сети в макете нет.

## Что не делать (сознательно исключено)

- Никакой геймификации кроме прогресс-линии и точек шагов — без бейджей, стриков,
  очков, конфетти.
- Никакого цвета — ни для успеха, ни для ошибки, ни для акцентов.
- Никаких карточек с тенями и скруглениями («SaaS-kit»).
- Никаких ALL CAPS лейблов и стрелок «→» в кнопках/ссылках.
