# Справочник по потоковому вводу: функция input() и архитектура fed-stdin

Долговечный справочник по устройству, настройке и сопровождению потокового ввода данных в тренажёре «вкат.py» и консоли преподавателя CONNECT Console.

> **Закон Zero-Build / Offline-First:** тренажёр и консоль работают полностью автономно в браузере (Vanilla JS ES2020 + WebAssembly Pyodide) без внешних сетевых запросов и шага компиляции.

---

## 1. Архитектурный принцип (TL;DR)

В браузерной среде Pyodide отсутствует интерактивный терминал операционной системы с блокирующим ожиданием ввода с клавиатуры в реальном времени.

Для поддержки стандартной функции Python `input()` реализован паттерн **fed-stdin** (судейский потоковый ввод):
1. Все входные строки передаются в рантайм пакетом перед выполнением кода.
2. В изолированном пространстве имён функция `input()` переопределена: при каждом вызове она последовательно извлекает очередную строку из внутренней очереди `_VKAT_STDIN_LINES`.
3. Если код запрашивает больше строк, чем передано, инициируется исключение `EOFError` с понятным объяснением от модуля `FriendlyErrors`.
4. Свободный эксперимент ученика («Запустить») строго отделён от судейской автопроверки («Проверить»).

### Базовый пример Python и вывода

**Код программы:**
```python
name = input("Имя: ")
age = int(input())
print(f"Привет, {name}! В следующем году тебе будет {age + 1}.")
```

**Входные данные (stdin):**
```text
Алекс
19
```

**Вывод программы (stdout):**
```text
Имя: Привет, Алекс! В следующем году тебе будет 20.
```

*(Необязательный аргумент `prompt` выводится в `stdout` непосредственно перед считыванием строки, как в стандартном Python).*

## 2. Руководство для автора урока (Authoring Guide)

При составлении учебных материалов используются три механизма передачи входных данных:

| Механизм | Где объявляется | Назначение |
|---|---|---|
| `task.stdin` | На верхнем уровне объекта задачи | Начальное значение для панели ввода ученика `#stdin-editor`; в заданиях типа `predict` — видимый блок входных данных для расчёта прогноза |
| `tests[].stdin` | Внутри элементов массива `tests[]` | Входные данные для отдельного изолированного прогона автопроверки (clean run) |
| `tests[].stdout` | Внутри элементов массива `tests[]` | Ожидаемый перехваченный вывод программы для соответствующего `stdin` |

### Рельные мини-фрагменты заданий

#### 2.1. Вводный шаг в теме переменных (`content/start/01-variables.js`)
Вводное задание `var_5` знакомит ученика с функцией `input()`. Обязательно указывается флаг `optional: true`, чтобы не блокировать прогресс учеников, завершивших базу ранее:

```javascript
  id: "var_5",
  type: "code",
  tier: "main",
  optional: true, // выпускники базы сохраняют 100% зачёт
  title: "Ввод данных с клавиатуры: функция input()",
  explanation: [
    "Функция <code>input()</code> считывает одну строку входных данных.",
    "Каждый следующий вызов читает следующую строку."
  ],
  assignment: "Считай имя пользователя с помощью input() и выведи приветствие вида: Привет, <имя>!",
  starterCode: "# Считай имя и выведи приветствие\n",
  stdin: "Алекс",
  expectedOutput: "Привет, Алекс!",
  tests: [
    { stdin: "Алекс", stdout: "Привет, Алекс!" },
    { stdin: "Борис", stdout: "Привет, Борис!" },
    { stdin: "София", stdout: "Привет, София!", hidden: true }
  ],
  hints: [
    "Вызови input() и сохрани результат в переменную name.",
    { code: "name = input()\nprint(f\"Привет, {name}!\")" }
  ]
}
```

#### 2.2. Практическая задача на числа и строки (`content/practice/l2-io-input.js`)
Скриптовые задачи практикума (`l2_io_c1`–`l2_io_c4`) проверяются серией чистых прогонов на разных строках:

```javascript

  id: "l2_io_c2",

  starterCode: "# Считай два числа и выведи сумму\n",

    { stdin: "15\n27", stdout: "42" },
    { stdin: "0\n0", stdout: "0" },
    { stdin: "-10\n25", stdout: "15" },
    { stdin: "100\n-200", stdout: "-100", hidden: true }

```

#### 2.3. Задание на предсказание вывода (`type: "predict"`)
В заданиях на прогноз вывода свойство `stdin` отображает входные данные в специальном блоке правого поля, чтобы ученик видел значения, с которыми работает код:

```javascript
{
  id: "l2_io_p1",
  type: "predict",
  title: "Два числа из потока",
  explanation: [
    "Определи, что выведет программа при поданных входных данных."
  ],
  code: "name = input()\nage = int(input())\nprint(f'{name}:{age * 2}')",
  stdin: "Анна\n20",
  expectedOutput: "Анна:40",
  explain: "Первый input() возвращает 'Анна', второй int(input()) возвращает 20. 20 * 2 = 40."
}
```

#### 2.4. Потоковый ввод до конца (`EOFError`)
Продвинутая задача со звёздочкой (`l2_io_c4`), демонстрирующая чтение неопределённого количества строк через `try / except EOFError`:

```javascript
{
  id: "l2_io_c4",
  type: "code",
  tier: "star",
  optional: true,
  title: "Сумматор потока до конца ввода",
  assignment: "Считывай целые числа построчно до исчерпания ввода и выведи их сумму.",
  starterCode: "# Считывай числа до конца ввода через try/except EOFError\n",
  stdin: "10\n20\n30",
  tests: [
    { stdin: "10\n20\n30", stdout: "60" },
    { stdin: "5", stdout: "5" },
    { stdin: "\n", stdout: "0" } // пустой поток: 0 чисел
  ]
}
```

### Правила составления тестов для автора
1. **Разнообразие тестов:** обязательно включайте положительные, нулевые, отрицательные значения, а также строки с пробелами.
2. **Пустой поток:** в тестах скриптов используйте `stdin: "\n"` для подачи 1 пустой строки `""`, либо пустую строку `""` для 0 строк (немедленный EOF).
3. **Хвостовой перевод строки:** учитывайте, что Python-метод `splitlines()` автоматически отсекает хвостовой `\n` (строки `"a\n"` и `"a"` образуют одинаковую очередь `['a']`).
4. **Связь с форматом контента:** общее описание структуры тем, квизов и теории см. в [Спецификации формата контента (content-format.md)](content-format.md).

## 3. Руководство для учителя (Teacher & Classroom Guide)

### Различия между «Запустить» и «Проверить»

В редакторе кода ученику доступны две раздельные кнопки с принципиально разным назначением:

```
[Показать подсказку]         [Пропустить]  [▶ Запустить]  [Проверить]  [Следующее задание]
```

| Параметр | «▶ Запустить» (`#btn-exec`) | «Проверить» (`#btn-run`) |
|---|---|---|
| **Источник ввода** | Текущее значение из панели ученика `#stdin-editor` | Фиксированные эталонные тесты `tests[].stdin` |
| **Вывод** | Консоль `#console-out` (stdout или трассировка ошибки) | Консоль + плашка результата (`#result-box`) |
| **Зачёт задания** | **Нет** (не добавляется в `completedTasks`) | **Да** (при прохождении всех тестов) |
| **Кнопка «Дальше»** | Не отображается | Открывается при успешном зачёте |
| **Телеметрия в класс** | Не отправляет событие зачёта | Отправляет событие попытки и статуса решения |
| **Учебная цель** | Свободное экспериментирование, проверка гипотез | Контрольная оценка решения |

> **Надёжность судейства:** даже если ученик ввёл в панель `#stdin-editor` случайный мусор или буквы, вызывающие `ValueError`, нажатие кнопки **«Проверить»** выполнит чистый эталонный зачёт на тестах задачи. Экспериментальный ввод не ломает оценку программы.

## 4. Справочник для сопровождающего (Maintainer Reference)

### 4.1. Архитектура компонентов и изоляция

```
[Пользовательский интерфейс]
   ├── #pane-code: #stdin-panel → #stdin-editor (ручной ввод)
   ├── #pane-predict: #predict-stdin-box → #predict-stdin-view (видимый stdin)
   └── #screen-sandbox: #sandbox-stdin-panel → #sandbox-stdin-editor
           │
           ▼
[Мост CodeChecker (app/checker.js / app/checker-worker.js)]
   ├── RUN (runCode): передаёт customStdin
   └── CHECK (checkSolution): использует строго task.stdin / tests[].stdin
           │  Сериализация: JSON.stringify(stdinVal) → stdin_json
           ▼
[Изолированный Python-рантайм (Pyodide Web Worker / Fallback)]
   ├── _exec_user_code_proxy(..., stdin_json)
   ├── _json.loads(stdin_json) → list / splitlines()
   └── _SAFE_BUILTINS['input'] = _student_input
```

1. **Безопасная передача `stdin_json`:**
   * Аргумент передаётся в Python через `JSON.stringify(stdinVal)` и декодируется вызовом `_json.loads(stdin_json)`.
   * Это полностью исключает интерполяцию `null` в Python-код и устраняет риск ошибки `NameError: name 'null' is not defined`.
2. **Черновики ввода (`drafts`):**
   * В уроках ввод сохраняется с дебаунсом в `state.codeDrafts[taskId + '_stdin']` через `VkatStorage.saveDraftDebounced`.
   * При возврате к заданию черновик восстанавливается в `#stdin-editor`.
   * В песочнице черновик ввода сохраняется в ключе `__sandbox_stdin__`.
3. **Песочница (`app/sandbox.js`):**
   * Содержит пресет `input_io` («Ввод данных: input()»).
   * Поддерживает как выполнение через фоновый Web Worker (`bridge.runCode`), так и через локальный `fallbackRunCode` главного потока.

### 4.2. Точная матрица крайних случаев (Verified Matrix)

Поведение проверено прямыми прогонами рантайма `_exec_user_code` и функции `_student_input`:

| Входное значение `stdin` | Очередь `_VKAT_STDIN_LINES` | Поведение при вызовах `input()` |
|---|---|---|
| `undefined` / `null` | `[]` (длина 0) | 1-й вызов `input()` → `EOFError` |
| `""` (пустая строка) | `[]` (длина 0) | 1-й вызов `input()` → `EOFError` |
| `"\n"` (один перевод строки) | `['']` (длина 1) | 1-й `input()` возвращает `""`, 2-й → `EOFError` |
| `"\n\n"` (два перевода) | `['', '']` (длина 2) | Два вызова `input()` возвращают `""`, 3-й → `EOFError` |
| `"a\n"` (хвостовой перевод) | `['a']` (длина 1) | 1-й `input()` возвращает `'a'`. `splitlines()` отсекает хвостовой `\n` |
| `"a\nb"` (внутренний перевод) | `['a', 'b']` (длина 2) | 1-й `input()` → `'a'`, 2-й `input()` → `'b'`, 3-й → `EOFError` |
| `"a\nb\n"` (внутренний + хвостовой) | `['a', 'b']` (длина 2) | 1-й `input()` → `'a'`, 2-й `input()` → `'b'`, 3-й → `EOFError` |
| `"a\r\nb"` (Windows CRLF) | `['a', 'b']` (длина 2) | 1-й `input()` → `'a'`, 2-й `input()` → `'b'` (CRLF нормализуется) |
| `["x", "", "y"]` (массив) | `['x', '', 'y']` (длина 3) | 1-й → `'x'`, 2-й → `""`, 3-й → `'y'`, 4-й → `EOFError` |
| `input("Введи: ")` | Строка из очереди | Prompt `"Введи: "` пишется в `stdout`, возвращается строка |
| `input(None)` | Строка из очереди | Аргумент преобразуется `str(None)`, строка `'None'` пишется в `stdout` |
| Исчерпание очереди | `[]` | Возбуждается `EOFError('Программа просит больше ввода...')` |

#### Отличия между UI и Python:
* В UI панель ввода представляет собой многострочное поле `<textarea>`: каждая визуальная строка отделяется клавишей `Enter` (`\n`).
* В Python строки считываются без символа переноса строки `\n` на конце (стандартное поведение `input()`).
* При интерактивном выполнении в браузере паузы на ожидание пользователя нет: скрипт исполняется атомарно от начала до конца за один такт.
