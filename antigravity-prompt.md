# Промпт для Antigravity

Ниже — текст, который можно вставить как основной промпт/системную задачу. К нему нужно
приложить 4 файла: `architecture.md`, `design-system.md`, `lesson-mockup.html`, `start-mockup.html`.

---

Ты разрабатываешь standalone-тренажёр по Python для новичков, опоздавших в группу.
Полное ТЗ — в приложенном `architecture.md`, дизайн — в `design-system.md` и двух HTML-макетах
(`lesson-mockup.html`, `start-mockup.html`). Прочти все четыре файла перед началом работы —
ниже только выжимка и явные приоритеты, сам ТЗ не дублирую.

## Жёсткие ограничения (не отступать без явного обсуждения)

1. **Только HTML + CSS + vanilla JS.** Никакого React, Vue, Tailwind, сборщиков (webpack/vite),
   npm-зависимостей в рантайме. Причина — весь проект должен запускаться с флешки двойным
   кликом по `index.html`, без установки и без интернета.
2. **Python выполняется через Pyodide**, локально (файлы рантайма лежат в проекте, не грузятся
   с CDN в финальной сборке). Проверка кода ученика — это реальное выполнение его кода, а не
   сравнение текста/regex.
3. **Zero-network в собранном виде.** Шрифты (IBM Plex Sans/Mono) — локальные `.woff2`, не ссылки
   на fonts.googleapis.com. Проверь при сдаче: проект должен открываться и работать с
   выключенным интернетом.
4. **Дизайн — строго по `design-system.md`.** Не добавляй свои цвета, тени, скругления,
   анимации сверх описанных. Если чего-то не хватает в токенах — лучше спросить, чем
   придумать самостоятельно. Оба HTML-макета — это не референс «в целом», а конкретная
   вёрстка, из которой можно напрямую забирать разметку и CSS.

## Что нужно реализовать

1. **Движок проверки** (`checker.js`) с тремя независимыми слоями:
   - выполнение кода ученика через Pyodide и сравнение вывода/значений с эталоном задания;
   - разбор через `ast` (стандартная библиотека Python, доступна в Pyodide) — проверка, что
     использована требуемая конструкция задания (цикл, функция и т.д.), а не подмена результата;
   - лёгкий линтер на правила уровня PEP8 (длина строки, отступы, имена переменных) — вывод
     идёт в блок «как сделать лучше», **не блокирует** переход к следующему заданию.
2. **Загрузчик контента**, который читает файлы тем из `/content/*.json` (формат — на твоё
   усмотрение в разумных пределах, но простой и человекочитаемый, так как автор будет
   редактировать эти файлы вручную без разработчика).
3. **Навигация и состояние**: линейное прохождение тем и заданий, сохранение прогресса в
   `localStorage`, восстановление сессии при повторном открытии на этом же устройстве.
4. **Два экрана из макетов** как рабочие шаблоны (стартовый + экран урока), плюс любой
   недостающий связующий UI (например, экран перехода между темами или финальный экран
   «прошёл всё») — в том же визуальном языке, без придумывания нового стиля.
5. **Наполнение контентом** шести тем из `architecture.md` (переменные → строки), примерно
   20–30 заданий суммарно, с усиленным вниманием к темам «циклы» и «функции» — это
   самые проблемные точки для аудитории.

## Что осознанно не делать

Классы, рекурсия, сложное наследование, диагностический вход/умный скип тем, аккаунты,
серверная часть, синхронизация между устройствами, любая интеграция с внешними сервисами —
всё это явно вне MVP (см. `architecture.md`, раздел «границы MVP» и «открытые вопросы»).

## Формат сдачи

Готовая папка проекта, которую можно скопировать на флешку и открыть `index.html` в браузере
без каких-либо дополнительных шагов установки. Структуру файлов — по образцу из
`architecture.md` (раздел 7), но не обязательно один-в-один, если есть более разумный вариант —
объясни отклонение.

Если что-то в ТЗ противоречиво или недосказано — лучше уточнить вопросом, чем додумать
самостоятельно и разойтись с макетами.
